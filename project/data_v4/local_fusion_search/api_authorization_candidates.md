# 需要外部 API 授权才能验证的候选

本文件只登记，不执行。当前零成本搜索的网络调用为 0。

## 1. EDLR：证据增强的直接 LLM 重排

把已观察历史、B0/A/T/K 候选并集和仅由外层训练来源计算的候选转移证据交给 LLM，由 LLM 判断语义与统计是否一致。它与本轮数值门控的关键区别是融合器能直接读取 procedure 语义。

需要授权发送：已观察父技术、战术、清洗历史描述、候选 ID、训练计数/支持数；不发送 source、campaign、样本 ID、目标或未来文本。需要新 token 计费。

现有开发协议：`project/data_v4/protocols/evidence_augmented_llm_reranker_development_v1.md`。

## 2. LLM 完整候选置信度

请求 184 类或受限候选集的可比较 log probability/置信度，替代当前人为设置的 `1/rank` B0 分数。需要先确认 DeepSeek 接口是否提供可审计的候选 logprob；若不提供则不可执行。

## 3. LLM 自一致性不确定度

对同一历史运行多次或多个冻结 prompt，利用排名方差决定是否接受转移分支。会成倍增加请求和费用，并需要独立的新数据确认。

## 4. 新来源的 LLM 事件顺序抽取

从未参与本轮方法选择的 DFIR/叙事报告中抽取显式事件顺序与 procedure 文本，构建真正的前瞻确认来源。必须先冻结报告选择、事件抽取、人工核验、分支线性化和 group 独立性协议。

以上四项均未执行，旧 DeepSeek 授权不自动覆盖这些新 payload 或新请求。
